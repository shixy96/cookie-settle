## Red → Green

按以下顺序逐项添加测试、运行确认行为失败，再修改实现并重跑：

1. 后置路径父域冲突：断言前后 Cookie 完全一致；最初失败，较长路径条目消失。加入全批次清理预检查后通过。
2. 删除 API 持续失败：断言较早已删除 Cookie 仍恢复；最初收到“自动恢复未完成”。改为按差异逐项恢复后通过。
3. 编辑中页面手动设置 Cookie，取消或 Esc 关闭：最初状态等待超时。记录待刷新状态并在关闭／解除忙碌时补查后通过。
4. 编辑、导入、恢复默认成功后状态读取失败：三个入口最初都无法找到主面板保存提示。区分保存与刷新结果后通过。
5. 手动设置旧默认路径 → 只检查 → 更新默认 JSON → 重启 → 全部清理：最初残留旧 Cookie。读取配置时按需持久化明确配置的路径后通过。
6. 旧面板配置执行启用／清理：最初进入 Cookie 修改而非拒绝旧配置。将版本比较扩展到修改请求后通过。
7. 浏览器自动化入口：`npm run test:browser` 最初因脚本不存在失败。添加本地开发依赖、锁文件、统一命令和 CI 工作流；运行时发现并同步了旧测试“检查不写任何存储”的过时断言。

8. 复查发现保存等待期间按 Esc 关闭对话框，延迟到达的保存错误不可见：三个入口的新增测试均先确认错误节点位于隐藏对话框而失败。保存进行时阻止原生 cancel，结束后恢复 Esc 关闭，测试通过。

9. 复查发现回滚初始读取失败会跳过全部恢复：新增暂时读取失败测试先收到“自动恢复未完成”而失败。捕获读取错误后仍逐项恢复快照，最后再次读取校验；测试通过。无法确认清理范围时不盲目删除新 Cookie，最终不一致仍报告恢复未完成。

已有正确行为的覆盖测试先运行通过，再做职责重构：后台并发保存拒绝旧版本、失败请求不阻断队列、存储失败不修改 Cookie、状态无变化不反复写存储、表单归一化与其他组保留。没有把原本正确的行为伪造成失败测试。

后台服务、表单转换提取以及测试 fixture 解耦均在绿色测试保护下进行。每个行为修复的失败原因来自断言或可观察结果；浏览器启动的沙箱失败和按钮定位错误不计为有效红灯。
