# Cookie Settle · 功能走查助手

面向日常功能走查的 Cookie 工具。集中管理测试环境，支持分组或批量设置、清理、实时检查和配置导入导出，无需逐页打开控制台。

当前内置网盘的企业盘、团队空间和分享外链三组示例环境，可编辑名称、容器、代理地址与路径，或导入另一份配置，在不同功能和测试环境之间复用。目标域名由配置的顶层 `host` 指定，内置值为 `pan.baidu.com`；组内仍管理两个 `BP_NODE` 代理 Cookie。

适用于 Chrome 120+ 和支持 Manifest V3 的新版 Edge。无需安装 npm 依赖或执行构建；加载本目录即可。

## 安装

1. Chrome 打开 `chrome://extensions`；Edge 打开 `edge://extensions`。
2. 打开「开发者模式」，点击「加载已解压的扩展程序」。
3. 选择 `/Users/thierry_shi/Desktop/repo/shixy/cookie-settle`。
4. 在扩展菜单中固定 Cookie Settle，点击图标打开面板。点击「展开」可在独立标签页使用。

扩展更新后，在扩展管理页点击「重新加载」，再重新打开面板。

## 使用

- **启用 / 全部启用**：按对应路径写入两个代理 Cookie，随后回读校验。操作后手动刷新业务页面，或点击「刷新站点页」。
- **清理 / 全部清理**：单组清理只删除本组精确路径，保留其他组共用的根路径或父路径。全部清理同时覆盖当前配置、历史配置，以及这些路径和已打开目标站点页面可继承的代理 Cookie 路径（包括 `/`、父路径和当前页面的深层路径），一并移除选定路径上的 Secure / 非 Secure 两种代理 Cookie，不删除登录 Cookie。
- **图标角标**：显示当前浏览器中完整匹配配置的路径总数（1–32），不是当前页面的 Cookie 条数。两个值、host-only 域名和配置路径均匹配且没有同名冲突才计数；零命中隐藏数字。弹窗关闭时也随手动 Cookie 和配置变化更新，悬停可查看完整计数；读取失败显示 `?`，成功重查后恢复。
- **当前页状态圆点**：Logo 左上角的固定圆点只改变颜色，与原有数字角标共存。绿色表示命中配置且当前页面实际生效的两个 Cookie 值与配置一致，不要求 Cookie Path 等于配置路径；浅灰表示命中但全部未设置；橙色表示缺少项、值不一致或同名冲突；深灰表示检查失败。当前页面未命中配置时会清除原 Logo 自带的装饰点，显示无圆点的 Logo。状态点在 16px 图标下为 4.5px 圆点，带细浅色边缘，以便辨认。悬停显示当前配置名称、路径、实际 Cookie 的 Domain / Path 和具体原因，同时注明全局匹配路径数。每个标签页独立显示，切换页面、导航（包括 SPA 路径变化）、手动改 Cookie、修改配置及扩展启动后都会更新，无需打开面板。
- **检查状态**：每次重新读取浏览器真实 Cookie，包含在页面控制台或开发者工具中手动设置的值，不依赖扩展之前是否执行过「启用」。点击后自动展开检查结果。
- **已打开页面**：按实际页面 URL 匹配 Cookie，显示「已设置」「未设置」「缺少一项」「同名冲突」。展开可查看实际值、Domain、Path 和 HttpOnly 属性；重复打开同一路径的标签页合并显示。
- **全部代理 Cookie**：列出两个代理名称的全部实际条目，包含根路径、父域、非预设的深层路径，以及没有打开页面的路径。没有打开目标站点页面时仍能检查。原始明细默认收起，按需展开；刷新保留展开或收起选择。
- **预设路径匹配**：保留与配置的对比，逐路径显示「已启用」「未设置」「配置不一致」。每组展开后集中展示一次共用 Cookie 配置，路径列表只显示状态；值不一致、缺少项或同名冲突时展示对应差异，作用范围冲突保留 Domain / Path。该区域与数字角标继续采用精确配置匹配，不代替实际页面检查。因此仅通过 `Path=/` 生效时，当前页可以是绿色圆点，而预设状态仍显示作用范围差异、数字角标不计数。
- **编辑配置**：修改容器 ID、代理地址、路径和备注。保存只更新配置，点击「启用」才会写入 Cookie。
- **导入 / 导出配置**：使用 JSON 交换环境配置，不读取或导出登录 Cookie。导入前展示配置摘要，确认后替换配置。
- **恢复默认**：恢复扩展内置的示例环境配置。不会立即修改已有 Cookie。
- **刷新站点页**：按当前配置 `host` 刷新所有已打开的 HTTP 和 HTTPS 标签页，其他域名不刷新，可能中断页面上尚未完成的操作。

## 内置环境

| 环境 | 路径 | 代理端口 |
| --- | --- | --- |
| 企业盘与预览 | `/disk/cert`、`/buy/workspace`、`/disk/enterprise`、`/disk/cospace` | `8075` |
| 团队空间主页 | `/disk/main` | `8011` |
| 分享外链 | `/e/`、`/c/` | `8112` |

内置环境用于快速开始。请根据当前走查任务，在「编辑配置」中更新容器 ID、代理地址和页面路径；不同任务的配置可以分别导出保存，之后按需导入。

管理的 Cookie 名称固定为：

```text
BP_NODE_CONTAINER_ID
BP_NODE_PROXY_PASS
```

默认配置统一存放在 `default-config.json`，也可以直接将它作为导入配置的格式示例。`version` 固定为 `1`，环境 ID 必须唯一。为避免同名 Cookie 冲突，禁止根路径 `/`、重复路径和互相包含的路径。顶层 `host` 是不含协议、端口、路径和通配符的主机名，例如 `pan.baidu.com` 或 `review.example.com`。站点标题、Cookie 读写、页面检查、数字角标、圆点和刷新按钮均使用这个字段。HTTP/HTTPS 页面都参与检查；新写入 Cookie 继续使用 Secure 属性，组内 Cookie 模型不变。

旧版导入文件或已保存配置缺少 `host` 时，使用 `default-config.json` 中的 `host` 补齐；导出会包含补齐后的字段。域名通过 JSON 配置修改，导入确认框会显示目标站点。

域名配置不等于浏览器授权。当前发行包仍仅声明原有站点权限，没有增加全站通配符权限。使用其他站点前，需在 `manifest.json` 的 `host_permissions` 中声明该站点精确的 `http://主机名/*` 和 `https://主机名/*`，重新加载并由浏览器授权；否则导入保存及读写操作会明确失败。需要检查父域 Cookie 时，也需为相应父域声明精确权限；未授权的父域条目可能被浏览器隐藏。

历史清理路径按域名隔离：切换站点不会将旧站点路径带入新站点，切回后保留已记录的历史。升级前仅有路径、没有域名归属的旧历史不会自动用于删除；其 Cookie 仍保留，若对当前配置或已打开页面生效，仍可按生效范围检查和清理。

### 维护默认配置

`default-config.json` 是唯一的内置环境配置来源，由原配置文件迁移而来，包含当前的“首页机器 / 主端备用机器 / 外链机器”备注。首次使用和「恢复默认」都读取这份 JSON；源码与测试中不再维护另一份默认环境对象；核心测试使用独立的小型 fixture，不依赖示例环境的数量或内容。

修改默认域名、名称、备注、容器、代理地址或路径时，直接编辑这份文件，之后在扩展管理页重新加载扩展。浏览器中已经保存的自定义配置继续优先使用；需要切换到文件中的配置时，点击「恢复默认」并确认。配置更新后，点击「启用」才会修改 Cookie。

文件职责：

- `default-config.json`：内置环境数据。
- `default-config-loader.js`：读取、校验并缓存打包在扩展内的 JSON，为调用方返回独立副本。
- `config.js`：配置校验、路径匹配，以及状态检查、写入校验和页面圆点共用的 Cookie 差异计算。
- `config-editor.js`：将编辑表单值转换为经过校验的新配置，不依赖 DOM。
- `background-service.js`：接收注入的存储、Cookie、标签页与权限 API 和默认配置加载器，串行处理消息。
- `background.js`：注册并校验扩展消息入口，监听 Cookie / 配置变化；导航只检查变化的标签页，复用已有配置与全局计数。
- `badge-service.js`：合并角标更新请求，串行读取状态并显示匹配路径数或读取错误；复用面板已完成的检查快照，并丢弃处理中收到的过时快照。
- `page-indicator.js`：按标签页匹配配置、读取实际 Cookie、解释差异，并丢弃过期检查结果。
- `status-icon.js`：缓存 16px / 32px 状态图像，清除原 Logo 右上角装饰点，在左上角绘制状态圆点；不修改原始图片文件。
- `popup.js`：按环境 ID 和页面 URL 复用节点，保留原生焦点与展开状态。
- `popup.css`：支持原生 CSS 开合过渡时使用 240ms 动画；旧版浏览器使用原生即时开合，不再维护 JavaScript 高度动画回退。箭头旋转遵循同一节奏，支持系统减少动态效果设置。
- `constants.js`：固定的两个 Cookie 名称；不包含站点域名或默认环境数据。

## 手动设置后的检查

在网盘页面手动运行 `document.cookie = "BP_NODE_CONTAINER_ID=...; path=/disk/cert"`，或在开发者工具中编辑 Cookie 后，点击扩展的「检查状态」即可看到实际值。面板打开时也会监听 Cookie 变化自动更新；对话框打开或操作进行中收到的更新会在关闭／完成后补查；弹窗关闭期间角标仍会更新，下次打开面板时重新读取明细。编辑保存、导入确认和恢复默认结束后会恢复发起操作的控件焦点。自动刷新按 `group.id` 保留焦点与展开状态；配置重排不影响对应关系，删除当前聚焦组时回到“全部启用”。实际页面列表按完整页面 URL 保留状态；HTTP 与 HTTPS 同路径分别展示完整 URL，展开状态互不影响。

未填写 `Path` 的手动 Cookie 可能落在更深的默认路径，例如在 `/disk/cert/deep/test` 设置时落到 `/disk/cert/deep`。它会出现在「全部代理 Cookie」中，匹配到的页面也会展示它，即使预设路径没有对应配置。

当前页检查覆盖已授权的 HTTP 和 HTTPS 目标站点页面，按域名与路径边界匹配配置，忽略查询参数和 hash；会检查实际子路径的同名 Cookie，而不只检查配置父路径。Secure Cookie 在 HTTP 页面上不视为已设置。圆点绿色仅表示 Cookie 与配置一致，不代表业务页面已经刷新或代理服务可用。

检查使用浏览器 Cookie API，因此也能读取 `document.cookie` 无法读取的 HttpOnly 条目。这里只展示两个代理名称，不显示登录 Cookie。检查结果代表当前 Cookie 对 URL 的匹配情况，不是对过去网络请求的回放，也不代表后端测试服务可用。

## Cookie 边界

- 仅申请 `cookies`、`storage` 权限，以及 `http://pan.baidu.com/*`、`https://pan.baidu.com/*` 和 `https://baidu.com/*` 站点权限，不申请全部网站访问权限。`http://pan.baidu.com/*` 用于读取页面手动写入的非 Secure Cookie。额外的 `https://baidu.com/*` 权限用于列出已授权范围内 `.baidu.com` 父域上的两个同名代理 Cookie：Chrome 在只有 `pan.baidu.com` 权限时会从 `cookies.getAll` 结果中隐藏这些条目，可能导致漏报冲突。代码不会修改父域 Cookie。尚未授权 `http://baidu.com/*`，非 Secure 父域 Cookie 可能无法读取。
- 新 Cookie 为当前浏览器配置文件内的 host-only、Secure、SameSite=Lax 会话 Cookie，不设置跨会话的到期时间。浏览器的会话恢复机制可能保留它们，结束走查时请主动清理。
- 仅清理配置 `host` 及其同域 Domain 形式（例如 `pan.baidu.com` 和 `.pan.baidu.com`）的两种代理 Cookie；全部清理按当前/历史配置与已打开目标站点页面的路径边界扩展，包含其父路径 `/`。`BDUSS` 等登录 Cookie、无关路径和其他域名不会被修改。清理共享父路径会同时影响使用该 Cookie 的其他页面，明细中有提示。
- 根路径和父路径 Cookie 影响配置时仍阻止直接启用，提示先执行“全部清理”。父域（例如 `.baidu.com`）、分区 Cookie 或无关路径不扩大写入权限，保留范围外提示；父域冲突需在开发者工具的 Application → Cookies 中处理。
- 分区 Cookie 不参与常规设置/清理；如果 API 返回了分区条目，会显示提醒。
- 清理使用实际 Domain / Path 精确过期并回读校验，避免按 URL 删除选中共享父路径 Cookie。清理前先检查全部目标的父域同名冲突；设置／清理中途失败时，只删除恢复所必需的新 Cookie，并逐项尝试恢复，单项失败不阻断其他目标。
- 操作失败会尝试恢复操作前代理 Cookie 的值、域、路径及属性，并校验恢复结果。Cookie API 无法恢复原创建时间，批量操作也不是浏览器级原子事务；请避免同时使用其他 Cookie 工具，并在操作完成后刷新页面。
- 同一个后台实例中的操作串行执行，过期面板配置不能覆盖新配置或按新配置执行 Cookie 修改。普通弹窗关闭后已发送的操作仍由后台处理。队列和回滚快照只存在内存中，不保证浏览器崩溃或 Worker 在操作中被强制终止后的事务恢复；重新打开后应检查实际 Cookie。
- 检查状态时会记录明确配置过的路径；修改默认 JSON 并重新加载扩展后，“全部清理”仍包含这些历史路径。额外的生效路径在本次检查和清理时动态计算，不会写入配置或持久化历史路径。
- 配置保存成功但状态刷新失败时，主面板会保留明确提示，可点击“检查状态”重试。
- 浏览器扩展不会修改 Electron 客户端、手机或其他浏览器配置文件中的 Cookie，也不配置 Charles 的商业化接口代理。
- 不支持无痕窗口。自定义配置仅保存在本机 `chrome.storage.local`；默认配置从扩展包内读取，不向外部服务发送请求。
- 卸载扩展不会自动删除已经写入的 Cookie，卸载前请点击「全部清理」。

## 开发与验证

生产文件使用原生 JavaScript 模块、Manifest V3 Service Worker 和静态 HTML/CSS，无运行时依赖或远程代码。构建只收集运行文件并生成 ZIP，不进行转译。

开发测试需要 Node.js 22+（CI 使用 Node.js 24），以及 `zip` / `unzip` 命令用于打包与产物验证。Playwright 只作为开发依赖，不会打入扩展。

```sh
npm ci
npm run browser:install
npm test
```

- `npm run test:unit`：配置、Cookie 引擎、默认文件加载及后台消息测试。
- `npm run test:browser`：原有扩展交互、页面手动 Cookie 场景和故障回归测试。
- `npm run test:all` / `npm test`：先运行单元测试，再运行全部浏览器测试，任何一项失败都返回非零状态。
- Linux 首次安装浏览器可执行 `npm run browser:install -- --with-deps`。

`.github/workflows/tests.yml` 在 push 和 pull request 上执行依赖安装、浏览器安装和完整测试；失败时上传已有的截图产物。仓库须托管在支持 GitHub Actions 的平台才会实际触发此工作流。

浏览器测试使用 Playwright 自带的 Chromium 和独立临时配置，不访问日常浏览器数据。模拟业务页面会拦截网盘请求，仍保留真实 HTTPS 源及原生 Cookie 行为。`PLAYWRIGHT_BROWSERS_PATH` 可指定已有浏览器缓存；通常无需设置 `PLAYWRIGHT_MODULE`，默认使用锁文件安装的本地依赖。

测试覆盖手动设置／修改／删除、HttpOnly、父域冲突、失败恢复、对话框及忙碌期间更新、保存后刷新失败、历史路径跨默认配置更新与后台重启、并发编辑和存储失败。浏览器端默认配置集成场景会验证当前随包配置；核心引擎测试使用 `tests/fixtures.mjs` 的独立数据。

TDD 修复记录见 [docs/tdd-review.md](docs/tdd-review.md)。没有实测 Edge、Chrome 120 或测试代理服务本身的连通性；重启测试验证持久化状态，不模拟操作途中进程崩溃。

## 构建与分发

在项目目录执行：

```sh
npm run build
```

构建需要 Node.js 22+ 和 `zip` 命令，无需安装 npm 依赖；macOS 可使用系统提供的 `zip`。测试另外需要 `unzip` 和开发依赖。

版本号读取 `manifest.json` 的 `version`，产物为：

- `dist/cookie-settle-<version>/`：可直接加载的扩展目录。
- `dist/cookie-settle-<version>.zip`：分发压缩包，根目录即包含 `manifest.json`。

脚本按明确白名单收集运行模块、HTML/CSS、默认配置和图标，排除测试、开发文档、依赖及本地文件。新增运行文件时需要更新 `scripts/build.mjs` 中的白名单。重复构建会替换当前版本产物并清除目录中的旧文件，其他版本产物保持不变；所需文件缺失或压缩失败时保留上一份可用产物。源码更新后需重新执行构建。

将 ZIP 发给使用者，解压后在扩展管理页打开开发者模式，通过「加载已解压的扩展程序」选择包含 `manifest.json` 的目录。使用者无需 Node.js 或 npm。该 ZIP 不是签名 CRX，本脚本不执行商店发布。

分发前建议执行 `npm test`；浏览器测试包含直接加载 ZIP 解压产物、启用默认配置并清理 Cookie 的场景。

参考文档：

- Chrome Cookies API：`https://developer.chrome.com/docs/extensions/reference/api/cookies`
